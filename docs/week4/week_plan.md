# 第 4 周项目实践计划

## 本周目标

围绕“会议室无人时，灯光、空调或投影是否仍在运行”完成一条可复现的数据链路：原始数据生成 → 清洗 → 指标计算 → 图表 → 30 分钟占用预测基线 → Web 展示。当前没有真实设备历史导出，因此全部分析数据明确标记为 `data_mode=simulated`，只用于验证实现与分析方法。

## 交付任务清单

- [x] 将连续监测数据从 7 天扩展为 14 天，并补充数据来源、灯光、空调、投影和预约状态字段。
- [x] 复用并扩展清洗脚本，统一布尔值、枚举值、异常标签和数据质量报告。
- [x] 回答 3 个问题：无效运行何时集中、哪类设备无效比例最高、各会议室工作时段占用率如何。
- [x] 为每张图记录统计口径、分母、有效样本量和数字结论。
- [x] 建立“预测 30 分钟后是否有人”的可复现基线，采用前 10 天训练、后 4 天测试。
- [x] 在管理端新增“数据分析”页面，展示数据范围、结论、图表、基线指标和限制。
- [x] 增加清洗、分析和基线测试，并通过单命令复现完整流水线。
- [ ] 每位成员用本人 Git 身份提交自己负责的内容；不得由他人伪造提交作者。

## 完成判据

1. `python scripts/run_week4.py` 能从头生成全部数据、图表、指标和 Web 静态资源。
2. 清洗后恰有 14 天、3 个会议室、5 分钟间隔的数据，模拟来源不会被误当成真实数据。
3. 至少 3 张图都有问题、定义、样本和数字结论；基线有时间切分与测试指标。
4. `python -m unittest discover -s tests -p "test_*.py" -v` 与 `npm run build` 通过。
5. 管理端 `/manager/dataAnalysis` 可以看到结果与限制。
6. Git 历史中能检查到每位成员的真实贡献提交。
