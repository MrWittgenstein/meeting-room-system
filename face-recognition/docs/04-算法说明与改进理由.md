# 算法说明与改进理由

本组的自主实现集中在**预处理**与**阈值判断**两个环节，二者都属任务书界定的算法环节。
所有改进均在 `config.yaml` 中留有开关，可用 `scripts/ablation.py` 一键复现对比实验。

> **证据说明**：下文的量化结论全部来自本组自建数据集（4 名对象共 62 张样本）上的
> 受控消融实验。所有变体沿用同一套注册集与同一套测试集，
> 差异只来自被关掉的那一项改进。完整数据见 `data/eval/ablation/summary.md`。

# 关键环节一：预处理 —— 输入归一化与关键点对齐

## 1.1 输入归一化

### 要解决的问题

把手机拍摄的 3072×4096 原图直接送入 YuNet 检测器，同一张脸会检不出、
或者检出的框明显偏小。实测同一张照片：

| 输入方式 | 检测置信度 | 检出框尺寸 | 折合人脸占比 |
|---|---|---|---|
| 原图 3072×4096 直送 | 0.679 | 485 × 542 | 2.09% |
| 长边缩到 1280 后再送 | **0.938** | 259 × 367（还原到原图约 829 × 1174） | 7.74% |

原图直送时检出的框面积只有准确值的 **27%**，置信度也掉到及格线附近。

### 原因

YuNet 的锚框尺度与输入分辨率绑定。输入尺寸远超训练时的尺度时，
模型输出的框会退化成只覆盖人脸的一部分，置信度随之下降。
这一条在摄像头场景下永远不会暴露——树莓派摄像头是 640×480，人坐得近，
本来就是"合适"的分辨率；只有换成高分辨率手机照片才会现形。

### 方法

```python
# face_engine/detector.py: _normalize / _rescale_face
scale = min(1.0, max_long_side / max(H, W))     # 只缩不放
work  = cv2.resize(frame, (W*scale, H*scale), interpolation=cv2.INTER_AREA)
raw   = detect_on(work)
raw   = rescale_face(raw, 1/scale)              # 框与 5 点关键点乘回原图坐标
```

- **只缩不放**：摄像头画面本来就够小，放大只增加算力不增加信息。归一化是绕原点等比缩放，没有平移，因此框和关键点各自乘 `1/scale` 即可还原。
- **对齐仍在原图上做**：检测在缩小图上进行（够用且快），但对齐裁剪回到原图，
  保留更多细节供特征提取使用。
- 人脸占比 `r = (w_f × h_f) / (W × H)` 是对缩放不敏感的比例量，
  因此归一化之后，"人脸够不够大"这条阈值在手机照片和摄像头画面之间才可比。

### 参数

`config.yaml → preprocess.enabled`（默认 `true`）、`preprocess.max_long_side`（默认 `1280`）

### 改进证据

| 配置 | 准确率（全样本） | 覆盖率 | 认成别人 |
|---|---|---|---|
| 完整方案 | **89.5%** | **89.5%** | 0.0% |
| 关闭输入归一化 | 42.1% | 47.4% | **5.3%** |

关掉后不仅覆盖率腰斩，还多出 5.3% 的误识——框偏移会把人脸裁得面目全非，
不同的人反而被裁成了相似的图。这是本组**收益最大**的一项改进。

## 1.2 关键点对齐的稳健估计

### 要解决的问题

58 张有效样本里有 **11 张**（19%）明明检出了人脸，却在"对齐"这一步被判失败丢弃，
而且 4 名对象全部中招，属系统性误杀而非个例。

### 原因

原实现直接使用 OpenCV 默认的 RANSAC 估计，并按内点数判定成败：

```python
transform, inliers = cv2.estimateAffinePartial2D(landmarks, _ALIGN_TEMPLATE)
if transform is None or inliers is None or int(inliers.sum()) < 3:
    return None
```

`estimateAffinePartial2D` 的重投影阈值默认 3.0，单位是**目标坐标系**——
而目标（112×112 标准模板）的坐标跨度只有 35–92。该变换的缩放比约 0.106，
换算回 3072×4096 的原图，3.0 相当于要求关键点误差不超过约 **28 px**。
人脸若有轻微表情或姿态，关键点偏差超过这个量级，于是 5 个点里只剩 2 个能算内点，
被 `>= 3` 的门槛拒掉。

同一类根因：**这条判据也是按 640×480 摄像头标定的**。
在低分辨率下 28 px 相对人脸尺寸很宽松，从不出错；到高分辨率照片上就变成了严苛条件。

### 方法

改用最小中值（LMEDS）稳健估计，用全部 5 个点求相似变换，不需要人工设定阈值：

```python
# face_engine/detector.py: _align
transform, _ = cv2.estimateAffinePartial2D(landmarks, _ALIGN_TEMPLATE, method=cv2.LMEDS)
```

RANSAC 分支保留在代码中（`alignment.method: ransac`），用于消融对比。

**为什么这不会放进来坏样本**：LMEDS 对 5 个点里的一致子集求解，异常关键点会被中值
压制。真出现离谱的对齐，后续的质量门控（在裁剪结果上算模糊度与亮度）和
相似度判定仍会把它拦下。也就是说，判定依据从"内点数"这个不可靠的代理指标，
回到了"识别得准不准"这个真实目标上。

### 参数

`config.yaml → alignment.method`（`lmeds` / `ransac`）、
`alignment.ransac_threshold`（3.0，仅 ransac 生效）、`alignment.min_inliers`（3，仅 ransac 生效）

### 改进证据

| 配置 | 准确率（全样本） | 覆盖率 | 认成别人 |
|---|---|---|---|
| LMEDS（当前） | **89.5%** | **89.5%** | 0.0% |
| RANSAC（原实现） | 63.2% | 63.2% | 0.0% |

覆盖率提升 26 个百分点，误识保持为 0——**纯增益，代价为零**。

# 关键环节二：阈值判断 —— 质量门控与人脸占比标定

## 2.1 质量门控

### 要解决的问题

模糊、过暗、过曝的人脸送去提取特征，会得到一个"看起来很正常"的向量，
不但白费算力，还可能在库里随机匹配到某个相似度不低的人，造成误识。

### 方法

在检测之后、特征提取之前做三道检查，任一不通过即丢弃该帧：

| 指标 | 计算方式 | 阈值 | 拦截目标 |
|---|---|---|---|
| 模糊度 | 人脸区域灰度图的拉普拉斯方差 | ≥ 60 | 运动模糊、失焦 |
| 亮度 | 人脸区域平均灰度 | 40 – 220 | 欠曝、过曝 |
| 人脸占比 | 人脸框面积 / 画面面积 | ≥ 2% | 人离得太远、人脸太小 |

```python
# face_engine/detector.py: _assess / _quality_pass / _is_valid_face
blur = cv2.Laplacian(cv2.cvtColor(face, cv2.COLOR_BGR2GRAY), cv2.CV_64F).var()
brightness = gray.mean()
```

### 参数

`config.yaml → quality_gate.{enabled, min_blur, min_brightness, max_brightness, min_face_ratio}`

### 改进证据

| 配置 | 准确率（全样本） | 覆盖率 | 认成别人 |
|---|---|---|---|
| 门控开启 | 89.5% | 89.5% | **0.0%** |
| 门控关闭 | 92.1% | 94.7% | **2.6%** |

关掉门控确实能多放行 5.2% 的样本，但代价是出现 2.6% 的误识。
**门控的价值在于防误识，而不是提高覆盖率**——这是门禁场景下的正确取舍：
放错人的代价远高于让本人多刷一次。

### 一处实现修正

原代码把"人脸占比"检查写在质量门控之外，导致消融实验里
`quality_gate.enabled = false` 其实关不干净，占比过滤仍在默默剔除样本。
现已把占比归入门控、随开关一起生效，消融结果才真实反映门控的作用。

## 2.2 人脸占比阈值 0.02 的标定

### 方法

阈值不该拍脑袋定。按人脸占画面比例分档统计，看每一档的识别表现：

| 人脸占比档位 | 样本数 | 识别正确率 | 拒识率 |
|---|---|---|---|
| < 2% | 4 | 0.0% | 100.0% |
| 2% – 5% | 5 | 100.0% | 0.0% |
| 5% – 10% | 18 | 100.0% | 0.0% |
| > 10% | 11 | 100.0% | 0.0% |

### 结论与取值依据

| 阈值取值 | 准确率（全样本） | 拒识率 | FAR |
|---|---|---|---|
| 0.05 | 76.3% | 23.7% | 0.0% |
| **0.02** | **89.5%** | **10.5%** | **0.0%** |

2%–5% 这一档的 5 张样本**全部识别正确**，说明它们本来是被 0.05 的阈值白白拒掉的。
放宽到 0.02 后准确率提升 13.2 个百分点，而 FAR 仍为 0，没有引入任何误识；
再往下（<2% 档）仍有 4 张失败，说明 0.02 正好卡在有效边界上。

**因此取 `min_face_ratio = 0.02`。**

# 其他自主实现

以下实现同样由本组设计，但在当前数据集上拿不出统计证据，故未作为关键环节申报。

## 3.1 暗光/侧脸检测增强回退链（检测环节）

主检测无结果时依次尝试：CLAHE 暗光增强 → 低阈值回退检测器（0.45）→
±12° 旋转检测，最后按 IoU ≥ 0.35 合并重叠框。CLAHE 只改像素不改几何，
框坐标 1:1 可用；旋转检测需把框与关键点经逆旋转矩阵映射回原图坐标。

**参数**：`detection.enhance.{enabled, clahe_clip, fallback_score_drop, rotation_angles}`

**证据缺口**：消融实验中关闭回退链，指标与完整方案**完全一致**
（均为 89.5% / 10.5% / 0%），因为本组样本全是室内均匀白光下的正脸，
该回退链一次也没被触发。要证明它有效，需要补拍弱光与侧脸样本。

## 3.2 多帧投票决策（阈值判断环节）

单帧比对结果噪声大，光照波动或检测框抖动会导致身份跳变。
维护长度 7 的滑动窗口，某身份占比 ≥ 70% 才输出"确认"；检测不到人脸立即清空窗口，
避免旧结果残留。输出四态：`confirmed` / `pending` / `unknown` / `lost`。

**证据缺口**：验证它需要同一段视频的日志对比
（`scripts/demo.py --no-voting` 与默认模式各录一次，再用
`scripts/eval.py --compare-logs` 比对身份跳变次数），本轮**尚未录制视频**。

## 3.3 多向量注册与向量化比对（比对环节）

每人可存多个注册向量（多角度注册），比对时取与库中该人所有向量的最大相似度，
相比"每人单向量"显著提升姿态与光照鲁棒性。
比对时预先把全库向量堆成归一化矩阵，识别时一次矩阵乘法完成与所有人的比对，
相比逐人循环，n 人时约提速 n 倍。

**参数**：`gallery.merge_strategy`（`max` / `mean`）

## 3.4 自适应阈值（阈值判断环节）

按每个用户注册向量之间的相似度分布计算个性化阈值，替代全局一刀切：

```
threshold = clamp(mean(sims) − k · std(sims), global_min, global_max)     k = 2.0
```

注册质量好（向量一致）的用户阈值自动收紧，注册质量差的自动放宽。

**参数**：`gallery.adaptive_threshold.{enabled, k, global_min, global_max}`

**证据缺口**：评测走的 `_decide_single` 目前只读全局拒绝阈值，
**没有实际使用 `match.threshold`**，因此该改进尚未被评测覆盖。
`scripts/eval.py --threshold adaptive` 已提供判定规则切换，但严格来说
引擎内部的单帧判定路径也需要同步改造，这一项**待补**。

## 3.5 帧间复用跳帧（性能优化）

摄像头相邻帧差异很小，每 `embed_every` 帧才走一次完整流水线，其余帧复用上一帧结果。
**参数**：`pipeline.embed_every`（默认 2）

# 复现方式

```bash

python scripts/eval.py --dataset "样本集" --out data/eval/final

# 消融实验：逐个关掉改进，量化贡献
python scripts/ablation.py --dataset "样本集"

python scripts/eval.py --dataset "样本集" --override preprocess.enabled=false

# 阈值标定对比
python scripts/eval.py --dataset "样本集" --min-face-ratio 0.05
```
