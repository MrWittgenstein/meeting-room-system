# 人脸识别模块技术实现文档

本文说明模块**是怎么实现的**——分层结构、模块职责、数据流、数据结构、接口契约、
性能与健壮性设计。算法改进的原理与实验证据见《05-算法说明与改进理由》，
测试数据与结论见《07-测试报告》。

---

## 一、模块定位

树莓派智能会议室系统中，人脸识别承担**会议室签到的身份核验与门禁放行**：
识别出"来的人是谁"，据此决定是否开门，并把结果上报后端。

| 项 | 说明 |
|---|---|
| 运行形态 | ① 树莓派本地端到端（摄像头 → 识别 → 舵机开门）② HTTP 服务，供小组框架调用 |
| 与本仓库其他部分的关系 | 本目录（`face-recognition/`）是**独立可运行**的人脸模块；`raspberry-pi/face_system/` 是另一套实现（YuNet + SFace），接在 `sensor_server.py` 中。两者尚未合并，见第十三节 |
| 对外依赖 | Python 3.13+、OpenCV、ONNX Runtime；树莓派端额外需要 picamera2 与 RPi.GPIO |
| 不含的内容 | 不含人脸照片与特征向量（`data/gallery.json` 不入库）；模型权重需按 `models/README.md` 自行下载 |

## 二、总体架构

```
                       ┌──────────────────────────────────────┐
   业务层              │ demo.py（本地实时演示）                │
   business           │ face_server.py（HTTP 接口）            │
                      │ servo_door.py  iot_reporter.py         │
                      └───────────────┬──────────────────────┘
                                      │ FaceResult
                      ┌───────────────▼──────────────────────┐
   决策层              │ recognizer.py   多帧投票 → 四态判定    │
   decision           │ gallery.py      人脸库 / 向量化比对 /   │
                      │                 自适应阈值             │
                      └───────────────┬──────────────────────┘
                                      │ 512 维特征向量
                      ┌───────────────▼──────────────────────┐
   算法层              │ embedder.py    特征提取（ONNX）        │
   algorithm          │ detector.py    预处理 → 检测 → 质量门控 │
                      │                → 对齐                 │
                      └───────────────┬──────────────────────┘
                                      │ BGR 帧
                      ┌───────────────▼──────────────────────┐
   采集层              │ camera.py   OpenCV / Picamera2 双后端 │
   capture            └──────────────────────────────────────┘

   组装：engine.py —— 把上述模块拼成流水线，对外只暴露 FaceEngine 一个类
```

**分层原则**：上层只依赖下层的抽象接口，不关心实现细节。
例如业务层拿到的永远是 `FaceResult`，不需要知道向量维度、阈值怎么算、
摄像头是 CSI 还是 USB。换模型、换摄像头后端都不影响上层代码。

## 四、两条主链路

### 4.1 注册链路

```
摄像头帧
   │
   ├─ FaceDetector.detect()          检测 + 质量门控 + 对齐 → 112×112 人脸
   │     └─ 未通过质量门控的帧直接丢弃，不计数
   │
   ├─ FaceEmbedder.embed()           112×112 → 512 维向量（L2 归一化）
   │
   └─ FaceGallery.register(user_id, name, emb)
         ├─ 追加到该 user_id 的 embeddings 列表
         ├─ 落盘 data/gallery.json
         └─ 重建全库归一化矩阵 + 重算该用户的自适应阈值
```

采集阶段按"正视 → 左转 → 右转"提示，默认取 5 张，构成**多角度注册**。
同一个人可多次注册追加向量，库里按 `user_id` 聚合。

数据集中转场景下注册照的挑选见 `scripts/eval.py` 的 `pick_enrollment`：
优先用人工挑选的注册集目录，不足时按 `检测置信度 × √人脸占比` 补足，
被选中的照片随即从测试集移除，避免注册集与测试集重叠。

### 4.2 识别链路

```
摄像头帧
   │
   ├─ 帧间复用判断（engine.recognize_frame）
   │     若上次结果未丢失 且 本帧不是第 embed_every 帧 → 直接返回上次结果
   │
   ├─ FaceDetector.detect()
   │     ├─ 输入归一化：长边 > 1280 才等比缩小（只缩不放）
   │     ├─ 主检测器（YuNet，置信度 ≥ 0.6）
   │     ├─ 无结果 → 回退链：CLAHE 增强 → 低阈值检测器（0.45）→ ±12° 旋转
   │     ├─ IoU ≥ 0.35 去重合并
   │     ├─ 几何过滤：框需完整落在画面内
   │     ├─ 质量门控：模糊度 ≥ 60、亮度 40–220、人脸占比 ≥ 2%
   │     └─ 5 点对齐 → 112×112（LMEDS 稳健估计）
   │
   ├─ FaceEmbedder.embed()           512 维向量
   │
   ├─ FaceGallery.match()            全库余弦相似度（一次矩阵乘法）→ 最相似身份
   │
   └─ VotingRecognizer.update()      7 帧滑动窗口投票 → FaceResult
         ├─ confirmed  窗口内该身份占比 ≥ 70%
         ├─ unknown    相似度 < 拒绝阈值，或"陌生人"占比达标
         ├─ pending    已匹配但证据不足
         └─ lost       本帧未检出人脸（立即清空窗口）
```

判定为 `confirmed` 且姓名在授权名单内 → 舵机开门；否则不放行。

## 五、关键数据结构

```python
@dataclass
class AlignedFace:              # detector.py 输出
    image: np.ndarray           # 112×112×3 BGR，已对齐
    bbox: Tuple[int,int,int,int]  # 框在**原图**上的坐标
    score: float                # 检测置信度
    quality: dict               # {"blur": float, "brightness": float}

@dataclass
class GalleryMatch:             # gallery.py 输出
    user_id: Optional[str]      # 最相似身份；库为空时为 None
    name: Optional[str]
    similarity: float           # 余弦相似度
    threshold: float            # 该用户的自适应阈值
    top_k: List[Tuple[str,float]]  # 前 3 名，调试用

@dataclass
class FaceResult:               # 最终对外结果
    status: Status              # UNKNOWN / PENDING / CONFIRMED / LOST
    user_id / name: Optional[str]
    similarity / threshold: float
    bbox / quality / votes: ...
    timestamp: float
```

**关键设计**：`detect()` 返回的 `bbox` 始终是**原图坐标**，即便检测是在缩小图上做的。
归一化是绕原点等比缩放、没有平移，所以框与关键点乘 `1/scale` 即可还原。
这样业务层画框、记录日志都不需要知道归一化的存在。

## 六、配置系统

所有可调参数集中在 `config.yaml`，改进点均留有开关以便消融对比。
`face_engine/config.py` 会把模型与人脸库的相对路径统一按 `config.yaml`
所在目录解析，因此**从任何目录运行脚本都能找到文件**。

| 分组 | 参数 | 默认值 | 作用 |
|---|---|---|---|
| `model` | `detector` / `embedder` | YuNet / w600k_mbf | 模型路径 |
| | `detect_input_size` | `[320,320]` | YuNet 输入尺寸（小=快） |
| | `score_threshold` / `nms_threshold` | 0.6 / 0.3 | 检测阈值 |
| | `top_k` | 1 | 每帧最多处理人数（签到场景单人） |
| | `embed_input_norm` | -1.0 | 输入归一化到 [-1,1]（insightface 约定） |
| `preprocess` | `enabled` / `max_long_side` | true / 1280 | **输入归一化**（自研） |
| `alignment` | `method` | `lmeds` | **对齐稳健估计**（自研，可切 ransac 消融） |
| `quality_gate` | `min_blur` / `min_brightness` / `max_brightness` / `min_face_ratio` | 60 / 40 / 220 / 0.02 | **质量门控**（自研） |
| `detection.enhance` | `enabled` / `clahe_clip` / `rotation_angles` | true / 2.0 / ±12° | 暗光侧脸回退链 |
| `gallery` | `merge_strategy` | `max` | 每人多向量取最大相似度 |
| | `adaptive_threshold.k` | 2.0 | 自适应阈值 `mean − k·σ` |
| `voting` | `window_size` / `confirm_ratio` / `reject_threshold` | 7 / 0.7 / 0.30 | 多帧投票与拒绝阈值 |
| `pipeline` | `embed_every` / `threads` | 2 / 2 | 跳帧与 ONNX 线程 |
| `backend` | `ws_url` / `device_id` / `room_code` | — | 后端对接 |

## 七、对外接口

### 7.1 HTTP 接口（`face_server.py`）

```bash
uvicorn face_server:app --host 0.0.0.0 --port 8000
```

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/face/health` | — | `{"status":"ok","users":N}` |
| POST | `/face/register` | multipart：`user_id`、`name`、`images`（多文件） | `{"user_id","name","registered_embeddings"}` |
| POST | `/face/recognize` | JSON：`{"image":"<base64>"}` | 见下 |
| GET | `/face/users` | — | `{"users":[{"user_id","name","embedding_count"}]}` |
| DELETE | `/face/users/{user_id}` | — | `{"deleted": user_id}` |

识别响应示例：

```json
{
  "status": "confirmed",
  "user_id": "s001",
  "name": "s001",
  "similarity": 0.5821,
  "threshold": 0.4231,
  "quality": {"blur": 231.4, "brightness": 128.6}
}
```

`status ∈ {confirmed, pending, unknown, lost}`。
**HTTP 接口是无状态的**——单张图进、立即出最佳匹配；多帧投票只用于本地实时链路。
这样队友无论用什么框架重构，接这个接口就行，不需要理解投票逻辑。

### 7.2 后端上报（`scripts/iot_reporter.py`）

识别结果随遥测消息上报，放在 `access_control` 字段：

| 字段 | 含义 |
|---|---|
| `face_detected` / `face_count` | 是否检出人脸 / 人数 |
| `recognized_names` | 本轮识别出的身份 |
| `authorized` | 是否授权放行 |
| `door_state` / `servo_angle` | 门状态 / 舵机角度 |
| `face_best_match` / `face_best_score` | 最佳匹配与相似度 |

反向接收后端的 `COMMAND`（开门 / 关门 / 设置舵机角度），执行后回 `COMMAND_ACK`。
**连接失败或未授权时不下发开门指令**，即"失败不放行"。

## 八、人脸库设计

存储为 JSON（明文，便于调试与迁移）：

```json
{
  "users": {
    "s001": {
      "name": "s001",
      "embeddings": [[0.013, -0.041, ...], ...]   // 每人多个 512 维向量
    }
  }
}
```

三个设计点：

1. **多向量存储**：同一人可存多个角度的向量，比对时取与库中该人所有向量的
   最大相似度（`merge_strategy: max`），比"每人单向量"对姿态和光照更鲁棒。
2. **向量化比对**：注册或变更时把全库向量堆成 N×512 的归一化矩阵并缓存，
   识别时用一次矩阵乘法 `matrix @ emb` 算出与所有人的相似度，
   相比逐人循环，n 人时约快 n 倍。
3. **自适应阈值**：按每个用户注册向量两两之间的相似度分布计算个性化阈值
   `clamp(mean − 2σ, 0.35, 0.55)`。注册质量好的用户阈值自动收紧，
   质量差的自动放宽，替代全局一刀切。

线程安全：读写加互斥锁，适配 HTTP 服务与本地链路并发访问。

## 九、性能设计

| 手段 | 说明 | 效果 |
|---|---|---|
| 帧间复用跳帧 | 摄像头相邻帧差异小，每 `embed_every` 帧才走完整流水线 | 特征提取计算量约减半 |
| 向量化比对 | 全库一次矩阵乘法 | n 人时约快 n 倍 |
| 输入归一化只缩不放 | 640×480 摄像头画面不做无用的放大 | 不浪费算力 |
| 检测在前、门控在后 | 低质量帧不进入特征提取 | 省算力且降误识 |
| ONNX 线程数可调 | 树莓派 4B 建议 2–4 | 平衡吞吐与占用 |

开发机实测（Windows，Python 3.14.2 / OpenCV 5.0.0 / ONNX Runtime 1.29.0）：

| 阶段 | 耗时 |
|---|---|
| 检测（含预处理） | 39.0 ms |
| 特征提取 | 6.2 ms |
| 库比对 | 0.1 ms |
| **合计** | **45.2 ms**（约 22 FPS） |

> 树莓派上的实测数据待补（设备不在手边）。

## 十、健壮性与降级

| 场景 | 处理 |
|---|---|
| 摄像头前几帧为空 | `read()` 内置 3 次重试 |
| 树莓派 Picamera2 不可用 | 自动回退 OpenCV VideoCapture |
| 主检测无结果 | 依次尝试 CLAHE 增强 → 低阈值检测器 → ±12° 旋转，最后 IoU 去重 |
| 人脸太小/太模糊/过曝 | 质量门控丢弃，不让劣质帧污染特征 |
| 高分辨率图像 | 长边归一化后再检测，避免检测退化为小框 |
| 关键点噪声 | 用 LMEDS 稳健估计而非依赖内点数判据 |
| 单帧结果抖动 | 多帧投票，人脸消失立即清空窗口 |
| 后端连接断开 | 自动重连；连不上时不影响本地识别与开门 |
| 未授权 / 识别失败 | **不放行**，留陌生人截图 |

## 十二、扩展点

| 想改什么 | 改哪里 |
|---|---|
| 换检测模型 | `config.yaml → model.detector`；若关键点顺序不同，调整 `detector._align` 的模板对应 |
| 换特征模型 | `config.yaml → model.embedder` + `embed_input_norm`；注意核对输入尺寸与归一化约定 |
| 调阈值 | `quality_gate.*`、`voting.reject_threshold`、`gallery.adaptive_threshold.*`，并跑 `eval.py` 重新标定 |
| 加一个新环节 | 在 `face_engine/` 下新建模块，在 `engine.py` 的流水线里插入，并在 `config.yaml` 留开关以便消融 |
| 换存储 | 替换 `gallery.py` 的 `_load` / `_save_locked`，比对逻辑无需改动 |

**评测基础设施可复用**：新增任何改进，只要在 `config.yaml` 里留一个开关，
`scripts/ablation.py` 就能自动跑出"开 / 关"对比表。

## 十三、已知限制

1. **与 `raspberry-pi/face_system/` 并存**，两套人脸实现尚未合并。
   本模块独立可跑、且带完整评测体系；`face_system` 接在 `sensor_server.py` 里。
   合并需要改动后者的调用与遥测协议，须与负责该部分的队友协同。
2. **无活体检测**：打印照片、屏幕照片可以骗过系统，属门禁类应用的严重缺陷。
3. **单人场景假设**：`top_k = 1`，多人同框只处理检测置信度最高的一张脸。
4. **无状态 HTTP 接口不做多帧投票**，单帧结果噪声高于本地实时链路。
5. **自适应阈值尚未在引擎的单帧判定路径生效**（`engine._decide_single` 仍用全局阈值），
   评测侧已支持 `--threshold adaptive` 切换。
6. **人脸库为明文 JSON**，未做加密存储；生产环境应考虑加密与访问控制。
7. 树莓派上的响应时间与业务联动录屏**尚未实测**。
