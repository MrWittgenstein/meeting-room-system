## 一、测试目标

依据任务书要求，验证系统在两类场景下的表现：

1. **已注册对象（本人）**：能否正确识别并放行
2. **未注册对象（非本人）**：能否正确拒绝而不误放

并给出准确率、FAR / FRR、拒识率，以及目标设备上的平均响应时间。

## 四、判定口径

**被拒绝的样本计入分母，不做静默剔除。** 这是本报告最需要说明的一点。

人脸识别系统可以主动拒绝输入（人脸太小、太模糊、相似度不足）。
如果只统计"被接受的那些样本"的准确率，一个大量拒识的系统会显得非常准确，
但这不反映端到端可用性。因此本报告同时给出两类准确率：

- **准确率（全样本）**＝正确识别数 / 全部已注册样本 —— 端到端真实通过率
- **准确率（接受的样本）**＝正确识别数 / 被放行样本数 —— 只看放行部分的纯度

两者必须一起看。指标定义：

| 指标 | 定义 |
|---|---|
| 漏检率 | 检不出人脸（含被质量门控拒）的样本 / 全部已注册样本 |
| 拒识率 FRR | 未能正确识别的已注册样本 / 全部已注册样本（含漏检、门控拒、相似度不足） |
| 误识率（认成别人） | 已注册样本被认成其他已注册对象 / 全部已注册样本 |
| FAR | 未注册样本被当作已注册人员放行 / 全部未注册样本 |

## 五、测试结果

### 5.1 总体指标

| 指标 | 数值 | 说明 |
|---|---|---|
| 漏检率 | 10.5% | 4 / 38，其中 4 张是检出后被质量门控拒掉 |
| **拒识率 FRR** | **10.5%** | 34 张正确 / 38 张总数 |
| 误识率（认成别人） | **0.0%** | 0 张 |
| **准确率（全样本）** | **89.5%** | |
| 准确率（接受的样本） | 100.0% | 覆盖率 89.5% |
| **FAR** | **0.0%** | 4 张未注册样本全部正确拒绝 |

### 5.2 混淆矩阵

行＝真实身份，列＝系统判定

| 真实 \ 判定 | s001 | s002 | s003 | s004 | 拒识 |
|---|---|---|---|---|---|
| **s001** | 8 | 0 | 0 | 0 | 0 |
| **s002** | 0 | 1 | 0 | 0 | 0 |
| **s003** | 0 | 0 | 10 | 0 | 0 |
| **s004** | 0 | 0 | 0 | 15 | 4 |
| **未注册** | 0 | 0 | 0 | 0 | 4 |

对角线以外没有任何数字：**没有一次把甲认成乙**。全部 4 例失败都是"拒识"，
即系统说"我不确定"，而不是"我认错了人"。在门禁场景下这是正确的失败方向。

4 例拒识全部来自 s004，且集中在其早期拍摄的远距离样本上——这属于设计内的
测试维度（远距离），不是随机故障。

### 5.3 按人脸占比分档

| 人脸占画面比例 | 样本数 | 识别正确率 | 拒识率 |
|---|---|---|---|
| < 2% | 4 | 0.0% | 100.0% |
| 2% – 5% | 5 | 100.0% | 0.0% |
| 5% – 10% | 18 | 100.0% | 0.0% |
| > 10% | 11 | 100.0% | 0.0% |

这张表直接回答"人站到多远系统就不认了"：**人脸占到画面 2% 以上即可稳定识别，
低于 2% 则全部失败**。它同时是 `min_face_ratio` 取 0.02 的依据。

### 5.4 阈值扫描

| 相似度阈值 | FAR | FRR | 准确率（接受样本） |
|---|---|---|---|
| 0.20 | **25.0%** | 0.0% | 100.0% |
| 0.25 | 0.0% | 0.0% | 100.0% |
| **0.30（当前）** | **0.0%** | **0.0%** | **100.0%** |
| 0.35 – 0.60 | 0.0% | 0.0% | 100.0% |
| 0.65 | 0.0% | 8.8% | 91.2% |
| 0.70 | 0.0% | 29.4% | 70.6% |

- 阈值 ≤ 0.20 时，有未注册样本的相似度达到 0.20 以上，会产生误放 —— 这是 FAR 的起点
- 阈值 ≥ 0.65 时，已注册样本开始被拒 —— 这是 FRR 的起点
- **0.25 到 0.60 之间存在一段宽阔的安全区间，FAR 与 FRR 同时为 0**。
  当前取值 0.30 位于该区间靠近保守一侧，留有余量。

### 5.5 平均响应时间（开发机）

| 阶段 | 耗时 |
|---|---|
| 人脸检测（含预处理） | 39.0 ms |
| 特征提取 | 6.2 ms |
| 库比对 | 0.1 ms |
| **单帧合计** | **45.2 ms** |

约合 22 FPS，实时性满足签到场景。**注意此为开发机数据**，
任务书要求的是目标设备（树莓派）上的响应时间，见第七节。

### 5.6 自研改进点消融实验

各变体沿用同一套注册集与测试集，差异只来自被关掉的那一项改进。

| 配置 | 准确率（全样本） | 拒识率 | 认成别人 | FAR | 覆盖率 |
|---|---|---|---|---|---|
| **完整方案** | **89.5%** | 10.5% | 0.0% | 0.0% | 89.5% |
| 关输入归一化 | 42.1% | 57.9% | 5.3% | 0.0% | 47.4% |
| 对齐改 RANSAC | 63.2% | 36.8% | 0.0% | 0.0% | 63.2% |
| 关检测增强回退链 | 89.5% | 10.5% | 0.0% | 0.0% | 89.5% |
| 关质量门控 | 92.1% | 7.9% | **2.6%** | 0.0% | 94.7% |
| 人脸占比阈值 0.05 | 76.3% | 23.7% | 0.0% | 0.0% | 76.3% |

**读表结论**

1. **输入归一化收益最大**：关掉后覆盖率 89.5% → 47.4%，还多出 5.3% 误识。
2. **关键点对齐的稳健估计是纯增益**：覆盖率 63.2% → 89.5%，误识仍为 0。
3. **质量门控防的是误识而非提覆盖率**：关掉后覆盖率升到 94.7%，
   但代价是 2.6% 的误识。门禁场景下这个交换不划算。
4. **人脸占比阈值 0.02 有据可依**：收紧到 0.05 会让覆盖率掉到 76.3%。
5. **检测增强回退链在本数据集上未被触发**（关闭后指标完全一致）——
   样本中没有暗光与侧脸场景，该改进的有效性尚未得到验证。

## 六、结论

1. 在 4 名对象、42 张测试样本上，系统**没有发生任何一次误识**（认成别人 0%，
   未注册放行 FAR 0%）。安全性指标全部达标。
2. 端到端准确率 89.5%，全部失败均为"拒识"而非"误认"。
   在门禁场景下，这是正确的失败方向。
3. 失效边界清晰：**人脸占画面低于 2% 时无法识别**，
   高于 2% 的 34 张样本全部正确识别。这为部署时的机位与提示语设计提供了依据。
4. 主要问题不是准确率，而是**拒识率偏高（10.5%）**。其来源是远距离样本，
   属于本次刻意纳入的测试维度。

## 七、局限与待补

### 测试覆盖的缺口

| 缺口 | 影响 |
|---|---|
| **样本量小**：4 名对象、42 张测试样本 | 单张样本即代表 2.4 个百分点，指标置信区间很宽 |
| **负样本仅 4 张** | FAR 的估计极不稳健，"FAR = 0%" 只能说明"这 4 张没放错" |
| s002 主集仅 4 张 | 该对象指标基本无统计意义 |
| **未覆盖弱光、强光、逆光** | 暗光增强回退链的效果无法验证 |
| **未覆盖口罩等遮挡** | 遮挡场景表现未知 |
| **未在树莓派上运行** | 目标设备的响应时间与帧率未知，本报告的 45.2 ms 是开发机数据 |

### 已识别的安全问题

- **无活体检测**：打印照片、手机屏幕上的照片可以骗过系统，这是门禁类应用的
  严重缺陷，当前实现未做任何防伪。
- 阈值判定只依赖单一相似度，未引入多帧一致性之外的第二种证据。

### 功能待补

- **自适应阈值改进尚未被评测覆盖**：评测路径走的是全局阈值，
  `engine._decide_single` 未使用每人的 `match.threshold`。
  算法已实现，但拿不出对比数据。
- **多帧投票改进尚未验证**：需要录制同一段视频的开关两种模式日志做对比，
  本轮未录制。
- 多人同框只处理检测置信度最高的一张脸（`top_k = 1`）。

### 下一步

1. 在树莓派上运行同一套评测，补齐目标设备响应时间。
2. 补拍弱光与侧脸样本，验证检测增强回退链。
3. 扩充负样本至 20 张以上，让 FAR 有统计意义。
4. 录制视频日志，验证多帧投票与跳帧的实际收益。
5. 改造 `_decide_single` 走自适应阈值，补齐该项消融数据。
