## 二、关键调用与输入输出

### 2.1 OpenCV —— 检测与对齐

**人脸检测**：`cv2.FaceDetectorYN`

```python
detector = cv2.FaceDetectorYN.create(model_path, "", (320, 320), 0.6, 0.3, top_k)
detector.setInputSize((w, h))          # 每次必须按实际输入尺寸重设
_, faces = detector.detect(frame)
```

- **输入**：`frame` 为 BGR 三通道图像，尺寸由 `setInputSize` 指定
- **输出**：`faces` 为 N×15 的 float32 数组，每行 `[x, y, w, h, 5×(x,y), score]`，
  5 个关键点依次为右眼、左眼、鼻尖、右嘴角、左嘴角
- **本组用法**：创建主检测器（阈值 0.6）与回退检测器（阈值 0.45）各一个；
  送入前先做长边归一化（见《04-算法说明与改进理由》1.1），检出的框与关键点再映射回原图坐标

**关键点对齐**：`cv2.estimateAffinePartial2D` + `cv2.warpAffine`

```python
M, _ = cv2.estimateAffinePartial2D(landmarks, ALIGN_TEMPLATE, method=cv2.LMEDS)
aligned = cv2.warpAffine(frame, M, (112, 112), flags=cv2.INTER_LINEAR, borderValue=0.0)
```

- **输入**：YuNet 输出的 5 点关键点；目标模板为 insightface 标准 112×112 五点模板
- **输出**：4 自由度的相似变换矩阵（旋转 + 等比缩放 + 平移），无剪切形变
- **本组用法**：改用 LMEDS 稳健估计替代默认 RANSAC，见《04-算法说明与改进理由》1.2

**其他 OpenCV 调用**

| 调用 | 用途 |
|---|---|
| `cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8))` | 暗光回退：仅对 YCrCb 的 Y 通道做对比度均衡，几何不变 |
| `cv2.getRotationMatrix2D` / `cv2.invertAffineTransform` | 旋转回退检测及其坐标反变换 |
| `cv2.Laplacian(..., cv2.CV_64F).var()` | 质量门控的模糊度指标 |
| `cv2.resize(..., interpolation=cv2.INTER_AREA)` | 长边归一化（缩小用 INTER_AREA 抗混叠） |
| `cv2.VideoCapture` / `cv2.VideoWriter` | 演示程序的取流与存视频 |

### 2.2 ONNX Runtime —— 特征提取

```python
session = ort.InferenceSession(model_path, sess_options=opts)   # opts.intra_op_num_threads = 2
out = session.run(None, {input_name: blob})[0]
```
`face_engine/embedder.py`

- **输入**：112×112×3，BGR 转 RGB，像素归一化到 [-1, 1]（insightface 约定），
  形状调整为 NCHW
- **输出**：512 维特征向量，再做 L2 归一化
- **本组用法**：线程数由 `pipeline.threads` 控制，树莓派 4B 建议 2–4；
  可切换 `embed_input_norm` 以适配不同来源的转换版模型

### 2.3 Pillow —— EXIF 方向校正

```python
from PIL import Image, ImageOps
rgb = ImageOps.exif_transpose(Image.open(path).convert("RGB"))
img = cv2.cvtColor(np.array(rgb), cv2.COLOR_RGB2BGR)
```
`scripts/eval.py: _read_image`

手机竖拍照片的像素数据通常是横放的，方向信息存在 EXIF 里。
`cv2.imread` 会忽略 EXIF，导致竖拍图片被当作横图处理。本组在读图时统一先做
`exif_transpose` 转正——这是本项目在数据集评测中踩到并修复的一个实际问题。

### 2.4 websocket-client —— 业务联动

`scripts/iot_reporter.py`

- **上行**：识别结果以 `access_control` 字段随遥测上报后端，含
  `face_detected` / `recognized_names` / `authorized` / `door_state` 等
- **下行**：接收后端的 `COMMAND` 消息（开门、关门、设置舵机角度），执行后回 `COMMAND_ACK`
- **失败处理**：未授权或识别失败时**不下发开门指令**，并记录陌生人截图

## 三、模型文件

| 模型 | 文件 | 大小 | 来源 | 协议 |
|---|---|---|---|---|
| **人脸检测** | `face_detection_yunet_2023mar.onnx` | 232,589 B | OpenCV Zoo（于仕琪团队） | Apache-2.0 |
| **人脸特征** | `w600k_mbf.onnx` | 13,616,099 B | insightface `buffalo_l` 包 | MIT |
| 对比用（未启用） | `w600k_r50.onnx` | 174,383,860 B | insightface `buffalo_l` 包 | MIT |

- `w600k_mbf` 为 MobileFaceNet 骨干 + ArcFace 损失，在 WebFace600K 上训练，
  输入 112×112，输出 512 维。
- 引入方式：仅使用其**预训练权重做特征提取**，未做任何微调或再训练。
  本组样本量（4 名对象）远不足以支撑人脸识别模型的训练或微调，
  强行微调只会过拟合，因此本组的自主工作集中在流程、预处理与判定规则上。
- 模型文件不随仓库分发，由 `scripts/download_models.py` 按上述来源下载。
